تابع `()fork` چیست؟

تنها راه ساختن Process جدید در لینوکس.

قبل از `fork` یک پروسه | بعد از `fork` دو تا پروسه:


![Fork](fork.png)

مکانیزم دقیق `fork` : 

1. پردازش والد در حال اجراست
   - شناسه یک تا : PID = 1000
   - شامل: کد، داده‌ها، پشته، هیپ
   - عملیات `fork` اجرا میشود

2. هسته سیستم عامل یک کپی می‌سازد:
   - فضای حافظه کپی می‌شود
   - همچنین File descriptors کپی می‌شوند
   - رجیسترها کپی می‌شوند

3. پردازش والد و فرزند شکل می‌گیرند

![After Fork](after_fork.png)


# تفاوت پروسه های Zombie و Orphans
## Zombie
مفهوم `Zombie Process` :
زامبی پروسه یعنی پروسه ای که تمام شده ولی هنوز در جدول پروسه باقی مانده.

1. پردازش فرزند کارش تمام می‌شود
   - عملیات `exit(0)`
   - "کارم تمام شد، می‌میرم"


1. فرزند از نظر حافظه و منابع تمیز می‌شود
   - حافظه آزاد شد 
   - فایل‌ها بسته شدند 
   - اما entry در جدول پردازش‌ها باقی مانده ✗
   - وضعیت: Z (zombie) 

1. منتظر والد است تا `wait` را فراخوانی کند
   - والد با `wait` فرزند را جمع‌آوری می‌کند
   - و entry جدول پردازش‌ها پاک می‌شود


حالا باید پروسه های زامبی رو چطور پیدا کنیم:

```bash
$ ps aux | grep Z
USER   PID  %CPU %MEM  STAT  CMD
user  1234   0.0  0.0   <Z+>   [zombie_child] <defunct>
```

از قسمت STAT میتوانیم متوجه بشیم که این یک پروسه ای هست که توی وضعیت Zombie قرار گرفته.

```bash
$ cat /proc/1234/status | grep State
State:  Z (zombie)
```

از این روش هم میتونیم متوجه بشیم.

```bash
$ top
Tasks: 150 total, 1 running, 148 sleeping, 0 stopped, 1 zombie
```

آنچه حفظ می‌شود:

- شناسه فرآیند (PID)
- کد خروج (Exit Status)
- ورودی جدول فرآیند
- اطلاعات استفاده از CPU/حافظه
- زمان خاتمه

آنچه آزاد می‌شود:

- حافظه (Memory)
- توصیف‌گرهای فایل (FDs)
- قطعه کد (Code Segment)
- پشته و هیپ (Stack/Heap)

## Orphan
چرا Orphan می‌شود؟

زمانی که یک Process والدش kill شود Orphan میشود.

### چرخه حیات فرآیند (Process Lifecycle)

### ۱. جریان عادی
- والد با fork() فرزند ایجاد می‌کند
- فرزند کارش را انجام می‌دهد → exit()
- والد با wait() وضعیت را می‌خواند و منابع را آزاد می‌کند

### ۲. جریان زامبی
- والد با fork() فرزند ایجاد می‌کند
- فرزند کارش را انجام می‌دهد → exit()
- والد wait() را صدا نمی‌زند → **زامبی** می‌شود

### ۳. جریان یتیم
- والد با fork() فرزند ایجاد می‌کند
- والد می‌میرد
- فرزند **یتیم** می‌شود → **init** (PID=1) والد آن می‌شود


وظایف `Init` :
- پروسه های `Orphan` رو باید adopt کنه
- وقتی میمیرند `()wait` بکند.
- از Zombie شدن شون جلوگیری کند

نکته (پروداکشنی): وقتی که پروسه های زامبی زیاد باشند سیستم کند میشود شاید بگیرد مصرفی ندارند که ولی CPU بهشون میرسه و CPU مصرف میکنند و ما باید اینها رو `Kill` کنیم.

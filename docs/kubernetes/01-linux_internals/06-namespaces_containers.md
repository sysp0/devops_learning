Linux Namespaces Overview
وقتی یک پروسه با `fork()` ایجاد می‌کنیم، فرزند تقریباً تمام محیط والد را به ارث می‌برد؛ از جمله PID namespace، فایل‌سیستم‌های mount شده، تنظیمات شبکه، زمان‌بندی و…  
اما در لینوکس می‌توانیم مشخص کنیم که فرزند همهٔ این‌ها را به ارث نبرد. اینجاست که **Namespace** وارد بازی می‌شود.

Namespace یک “محیط ایزوله” است که یک سری منابع را از هم جدا می‌کند. اگر یک پروسه را داخل یک namespace جدید بسازیم، آن پروسه فقط نسخهٔ خودش از آن منابع را می‌بیند، نه منابع سیستم اصلی. در عمل، این پایهٔ اصلی کانتینرهاست.

هر namespace یک نوع خاص از منبع را جدا می‌کند. مهم‌ترین موارد عبارت‌اند از:

- **PID Namespace**  
    پروسه‌ها شماره‌گذاری جداگانه دارند. یک PID داخل namespace ممکن است روی سیستم اصلی PID متفاوتی باشد.
- **Mount Namespace**  
    جدول mount مخصوص خودش را دارد. یعنی می‌توانی rootfs متفاوت یا mountهای جدا داشته باشی بدون اینکه روی سیستم اصلی اثر بگذارد.
- **Network Namespace**  
    هر namespace شبکهٔ خودش را دارد: interface مستقل، routing table مستقل، iptables مستقل.
- **User Namespace**  
    امکان جداسازی شناسه کاربر (UID/GID). پروسه می‌تواند داخل namespace روت باشد ولی روی سیستم اصلی کاربر معمولی.
- **UTS Namespace**  
    جداسازی hostname و domainname.
- **IPC Namespace**  
    صف پیام، semaphore و shared memory جداگانه.
- **Time Namespace**  
    ساعت سیستم و clock مخصوص خودش. برای شبیه‌سازی زمان در کانتینر کاربرد دارد.

همین ساختار باعث می‌شود یک کانتینر مثل یک سیستم جدا دیده شود، در حالی که همه‌چیز هنوز روی همان کرنل اجرا می‌شود.

# `unshare` Command
ما در لینوکس یک دستوری داریم که میتوانیم `NS` هامون رو مشاهده کنیم:

```bash
lsns
```

و میتونیم NS های یک پروسه رو از طریق زیر مشاهده کنیم:

```
ls /proc/1/ns
```

همچنین ما یک name space ای داریم که بصورت دیفالت وجود دارد, هر پروسه جدید ایجاد کنید داخل اون name space میشود.

اگر بخواهیم یک پروسه جزو یک ns خاص قرار بگیرد اول اون ns رو میسازیم و پروسه رو به اون اضافه میکنیم

حالا ما میتونیم هر پروسه ای رو داخل یک ns قرار دهیم با دستور unshare:

```bash
➜  ~ sudo unshare -p -f --mount-proc bash
# -p : PID
# -f : Fork 

root@Ghasemi-PC:/home/ghasemi_r# ps
    PID TTY          TIME CMD
      1 pts/6    00:00:00 bash
     37 pts/6    00:00:00 ps
root@Ghasemi-PC:/home/ghasemi_r# 
```

با به دستور `unshare` میگیم این مواردی که بهت ورودی میدم رو جدا سازی کن.

ما وارد یک محیط دیگری میشیم و اگر ps بگیریم bash ای که داخلش قرار داریم `PID 1` رو دریافت میکند.

> حتما باید دستور `mount-proc--` رو بدهیم و گرن پوشه `proc/` اضافه میشود و ما تمام پروسه هارو میبینیم.

حالا اگر از روی ns اصلی پروسه های اون bash مون رو که `unshare` زدیم یک `pstree` بگیریم pid اصلیش رو پیدا میکنیم:

```bash
➜  ~ pstree 757887 -p
zsh(757887)───sudo(1808439)───sudo(1808443)───unshare(1808444)───bash(1808445)
```


کانتینر هم دقیقا همین کار را انجام میدهد. مفهوم کانتینر: 

پروسه ایست که توسط `ns` و `Cgroups` محدود شده است. کوبرنتیز و داکر این عملیات رو برای شما راحت تر میکند بجای اینکه از `unshare` استفاده کنیم.

> داخل `unshare` تمامی چیز هارو به ارث برده است به جز اون هایی که ما مشخص کردیم.


# `nsenter` Command

فرض کنید ما یک app.py داریم که داخل یک `ns` قرار دادیم. حالا یک مشکلی دارد برای ارتباط با دیتابیس :

![app db connection](ns_app_db.png)

حالا ما میخواهیم دلیل اینکه نمیتواند به دیتابیس متصل شود رو پیدا کنیم، پس نیاز داریم که خودمون رو داخل اون `NS` قرار دهیم.

حلا باید `bash` خودمون رو بندازیم توی `ns -> Network` تا بتونیم خودمون بررسی کنیم که چرا به DB وصل نمیشود.

این کار رو با دستور `nsenter` انجام میدهیم، بصورت زیر :

در مرحله اول با دستور `lsns`  میتونیم ببینیم که چه دستور هایی چه `NS` هایی ساخته اند و `PID` کسی که این `NS` رو ساخته پیدا کنیم :

```bash
4026533642 mnt 2 1808444 root unshare -p -f -n --mount-proc bash
```

در اینجا `1808444` مربوط به `PID` دستور `unshare` هستش، ما با این `PID` حالا میتونیم وارد هر یک از `NS` های این دستور بشیم

```bash
sudo nsenter --target 1808444 -n
# -n : Just Network
```

> با اپشن `n-` مشخص میکنیم که فقط مارو ببر توی `NS` شبکه


با این دستور میتونیم خیلی راحت داخل کوبرنتیز و داکر عملیات `troubleshoot` رو انجام بدهیم. همچنین روی محیط پروداکشن ما ایمیج هامون برای مثال اگر `Alpine` باشه دستور `ping` وجود ندارد، داخل پروداکشن ما دسترسی به اینترنت نداریم و عملا نمیتونیم از روی کانتینر این عملیات رو انجام بدهیم. 

برای  اینجور مواقع ما از این دستور استفاده میکنیم که وارد اون `NS` بشویم.
